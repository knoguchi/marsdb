# エグゼキュータ

エグゼキュータ(`marsdb-query/src/executor.rs`、加えて算術・スカラー
関数・時制関数・値比較の 4 つの補助モジュール)は論理プランを行に
変え、プランが扱わないすべてを適用します: 射影、集約、整列、書き込み
句、そして実行制限の強制。MarsDB 最大のコンポーネントですが、理由は
アルゴリズムの高度さではありません — ここが Cypher の意味論が実際に
住む場所であり、Cypher には大量の意味論があるからです。

## 行と束縛

データフローの単位は `BindingRow`: 変数名から `Binding` へのマップで、
束縛はノード参照、エッジ参照、計算された値、リスト、またはパスです。
演算子は行のベクタを取り、行のベクタを返します。スキャンはノードごとに
1 行を生み、`Expand` は入力行ごとに 0 個以上の後続行を生み、`Filter` は
行を落とします。ノードとエッジは実体化されたレコードではなく *id* で
移動します — プロパティは第 3 章の単一プロパティ読み取りパスで必要時に
取得され、あのパスの性能が重要なのはまさにこのためです。

ユーザの Cypher からは決して見えない 2 つの隠し束縛キーが構造的な
仕事をします: 1 つは `OPTIONAL MATCH` の結果行を、それを播種した外側の
行に相関づけ(左外部の null 埋めを、何にもマッチしなかった外側の行に
正確に適用できるように)、もう 1 つは `MERGE` の行が作成パス由来か
マッチパス由来かをタグ付けし、行が見えるようになる前に消費・除去
されます — `ON CREATE SET` と `ON MATCH SET` が各行の分岐を知る方法
です。

## プランを歩く

プラン評価は再帰的ウォークです。スキャンは `NODES`、ラベル
インデックス、またはプロパティインデックス検索をイテレートします。
`Expand` は各入力行の束縛済みノードを、第 3 章の境界関数を使って
`ADJ_OUT` または `ADJ_IN` 上のプレフィクスレンジに変えます(無向
ホップは両方を、エッジ id で重複排除しながら)。`VarExpand` は入力行
ごとに有界 BFS を走らせ、ホップ間のエッジ同型性を強制するパターン
全域の除外エッジ集合を通します。

`OPTIONAL MATCH` はサブプラン全体を左外部の意味論で包みます: マッチを
生んだ外側の行はそれを保持し、何も生まなかった外側の行は、その
オプションパターンが*新規に*束縛したはずの変数だけを `Null` で埋め
られます — 再登場した変数は既存の束縛を保ち、それが、束縛済みの `a` を
持つ `OPTIONAL MATCH (a)-[r]->(b)` が「この `a` を延長するか、`r` と
`b` を null にする」を意味する理由です。

## 有界実行

ウォーク内のすべての長時間ループは `ExecutionGuard` に立ち寄り、
呼び出し側の `ExecutionOptions` を協調的に強制します:

- **キャンセル** — atomic bool に裏づけられたクローン可能なトークン。
  別スレッドから反転でき、ガードはループのチェックポイントで確認
  します。
- **タイムアウト** — 一度計算された期限を同じチェックポイントで比較。
- **行と展開の制限** — 中間行数、結果行数、そして歩いた隣接エントリ
  ごとに増える relationship-expansion カウンタ。

設計の要点はこれらを*どこで*検査するかです: 実体化の後ではなく、
プラン評価の最中。暴走した `MATCH (a)-->(b)-->(c)` は制限を*超えた*
ときにエラーになります。無制限の中間結果を先に構築してメモリの被害が
出た後で切り詰めるのではなく。プリエンプションも監視スレッドも
ありません — 他のあらゆる場所と同じ「バックグラウンドスレッドなし」
ルールです — だから制限の粒度はチェックポイントの粒度であり、それが
協調的強制の正直なコストです。

ガードはもう 1 つ、物語つきの状態を運びます: 削除済みエッジ id から
型名へのマップです。Cypher は同じ文の中で先に `DELETE r` した*後*の
`type(r)` の読み取りを許します — リレーションシップの型は生涯不変
なので生きたレコードを要しません — 一方、削除済みエッジの
*プロパティ*を読むのはエラーです。削除パスは各エッジの型を除去直前に
記録し、`type()` の評価は生きた検索が失敗したときだけこのマップに
フォールバックします。これは第一原理の設計では決して出てこない種類の
意味論的詳細です。適合テストから来たもので、コードコメントは正確な
テストシナリオを引用しています。

## 式と 3 値論理

述語と射影の評価は Cypher の SQL 風 3 値論理を実装します: `null` を
含む比較は unknown、unknown は通常の真理値表で `AND`/`OR` を伝播し、
`WHERE` は述語が確定的に true の行だけを残します。プランナの章で
これが噛みつく場所を 1 つ見ました(false に潰された unknown の上の
`NOT` はそれを true に反転させてしまう)。エグゼキュータはこの規律を、
全演算子が共有する値比較モジュールで一様に強制する場所です。

値は動的型付けで、型エラーは設計上*実行時*エラーです(第 5 章の
意味パスは構造的種別だけを検査します)。非互換型間の比較はエラーでは
なく `false` — Cypher と一致 — 一方、誤った型への算術は型付き
`QueryError::Type` でエラーになります。

## 集約

Cypher に `GROUP BY` キーワードはありません: 集約する `RETURN` や
`WITH` では、非集約の項目*が*グループ化キーです。エグゼキュータは
それらの項目の値をキーに行をグループへ畳み込み、グループごと・集約
項目ごとに 1 つのアキュムレータを駆動します — `count`、`sum`、`avg`、
`min`、`max`、`collect`、加えてアキュムレータごとに追跡される
`DISTINCT` 変種。

グループ化にはハッシュ可能なキーが必要ですが、MarsDB の値型は
`Eq`/`Hash` を導出できません — `f64` を含み、Rust の標準ライブラリは
それのハッシュを正しく拒むからです(IEEE 浮動小数に反射的等価は
ありません)。解は並行の `HashKey` 型で、浮動小数を*ビットパターンで*
ハッシュします。トレードオフは定義の場所に文書化されています: 通常の
浮動小数グループ化は影響を受けず(等しい浮動小数は等しいビットを
持つ)、端では `NaN` が `NaN` とグループになり(IEEE の `NaN != NaN` と
異なる)、`+0.0`/`-0.0` は別グループに落ちます。ノードとエッジは id で
ハッシュされます — グラフ同一性、他の場所の等価と一貫。`DISTINCT` の
既出集合も同じ型を使います: 同じ問題、同じ解、1 つの定義。

## 2 つの出力レーン

実体化実行 — 既定 — は `QueryResult` を生みます: 列名、値の行、文
ごとの書き込み統計。`ORDER BY`、`SKIP`、`LIMIT`、`DISTINCT` はこの
段階で、射影済みの列に対して適用されます(`ORDER BY` キーが射影の
エイリアスを参照できるのはそのためです)。

ストリーミングレーン(`execute_streaming_with_options`)は行を
1 つずつ呼び出し側のシンクに押し出し、結果サイズによらず有界メモリで
動きます。その契約は設計として厳格です: 本当にストリームできる形 —
単一の素の `MATCH ... RETURN`、`SKIP`/`LIMIT` は可 — だけを受け入れ、
`ORDER BY`、集約、`DISTINCT`、`WITH` には*エラー*を返します。それらの
構文は 1 行でも出力する前に全行を見なければならず、そのために黙って
実体化する「ストリーミング」API はメモリについての嘘になります。
MarsDB は嘘より拒否を選びます。行数制限は早期終了を兼ねます: 「停止」を
返すシンクはスキャンを終わらせます。

書き込み句(`CREATE`、`MERGE`、`SET`、`DELETE`、`REMOVE`)は同じ行
ストリームに対して実行されます — パターンが束縛した各行について、
第 4 章の `_in_txn` 層を通じて、文の 1 つのトランザクションの中で
ミューテーションを適用し — その効果を文の `QueryStats` に数えます。

次章は完成した結果がプロセスを出ていくのを追います: 行はどう C ABI を
越え、必要以上にコピーされることなく、どう Arrow レコードバッチ、
Python オブジェクト、Go のマップになるのか。
